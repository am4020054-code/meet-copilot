# Release 2: замеры, что осталось и задачи для Codex

Денис, это разбор после твоего Release 2 (локальный индекс вместо всего контекста в запросе).
Раздел «Задачи для Codex» можно отдать агенту как есть.

## Коротко

- Release 2 снял главную задержку. Раньше модель перечитывала весь контекст на каждый запрос
  (32 тыс. токенов, первый текст через ~11 с). Теперь в запросе 1,2–2,4 тыс. токенов, первый
  текст через ~2 с при любом размере папки, и лимит токенов в минуту больше не мешает.
- Узкое место теперь — поиск. Он сравнивает слова, поэтому английский вопрос не находит русский
  абзац. На трёх вопросах из шести модель ответила «в документах этого нет», хотя это там есть.
- В этом PR: мелкие правки скорости, отсечение русских окончаний в поиске, отчёт о файлах,
  не попавших в индекс, и замерщики.

## Как мерили

Контекст — 13 файлов документации реального SaaS-продукта на русском, 185 КБ, 491 абзац в
индексе. Шесть технических вопросов на английском из `bench/questions.txt`. Модель
`gemma-4-31b`, бесплатный аккаунт. Один прогон по шесть запросов, так что это порядок величин.

```sh
python bench/latency.py --context <папка> --real --show   # задержки и ответы серверным кодом
python bench/latency.py --context <папка>                 # фазы запроса по отдельности
python bench/expand_probe.py --context <папка> --answers  # поиск как есть и с ключевыми словами
```

## Скорость

| | Release 1, весь контекст | Release 2 | Release 2 + этот PR |
|---|---|---|---|
| Токенов в запросе | 32 тыс. | 1,2–2,4 тыс. | 1,2–2,4 тыс. |
| Первое предложение (`say`) | ~10,5 с | 1,75 с | 0,9 с |
| Вся карточка (`answer`) | 13,8 с | 3,4 с | 2,9 с |
| Слов в `SAY` | 50–75 | 27–56 | 19–28 |

Два замечания к таблице:

- Если в `SAY` есть цифры, Release 2 ничего не показывает до конца ответа. Для таких ответов
  первый текст на экране — это время всей карточки. С коротким `SAY` это 2,5–3,9 с.
- Примерно раз в 15–20 запросов шлюз отвечает через 14–20 с. Это не зависит от размера запроса и
  не связано с простоем: после 4,5 минут тишины первый запрос был обычным.

## Поиск: что находится, а что нет

`plain` — `ContextIndex.search` как в Release 2. `expanded` — перед поиском один маленький запрос
к модели превращает вопрос в ключевые слова на языке документов (`bench/expand_probe.py`).

| Вопрос | plain | expanded |
|---|---|---|
| Стек и почему | верно | верно |
| Коммунальные платежи: по площади или по счётчикам | неполно: только по площади | верно: три способа |
| Развёртывание и резервные копии | верно | верно, другие детали |
| Какие интеграции работают, какие в планах | «в документах нет» | «в документах нет» |
| Цены и тарифы | «цены не указаны» | верно, все тарифы с ценами |
| Изоляция данных и хостинг | мимо: про шифрование паспортов | частично: хостинг в РФ, про изоляцию нет |

Шаг с ключевыми словами занял 1,4–3,7 с (медиана 1,8 с) на новом соединении и без стриминга.

Вторая причина промахов — окончания. Запрос ищет по началу слова, а русские слова меняют конец:
«тарифы» не находили «тарифные планы», «интеграции» не находили «интеграция». Это касается и
русских вопросов. В PR добавлено отсечение окончаний в `terms()`: по русскому вопросу о цене
раздел «Тарифные планы» после этого попадает в выдачу, а до этого не попадал. Вопрос про
интеграции по-прежнему не находится: в документах это названо «заглушки» и «отложено».

## Что в этом PR

| Правка | Где |
|---|---|
| Соединение со шлюзом открывается заранее: −0,5…1,2 с на запрос | `hints.WarmConnection`, `gateway_stream` |
| `SAY` — одна строка, до двух коротких предложений | `hints.FORMAT` |
| Отсечение русских окончаний в поисковых словах | `context_index.stem`, `terms` |
| Файлы не `.md`/`.txt` из папки перечисляются в статусе, на экране и в консоли | `context_index.py`, `server.py` |
| Замерщики и этот разбор | `bench/` |

Тесты: `python -B -m unittest discover -s tests` и `node tests/core.mjs`. Добавлены проверки на
русские окончания и на список пропущенных файлов.

## Задачи для Codex

1. **Поиск между языками.** Нужно, чтобы английский вопрос находил русский абзац без ручных
   `search_aliases`. Два варианта, сравнить на `bench/questions.txt`:
   - Ключевые слова на вопрос, как в `bench/expand_probe.py`, но объединять выдачу `plain` и
     `expanded` (например, по три абзаца из каждой), а запрос ключевых слов запускать по
     незаконченной фразе в `considerPreliminary`, чтобы к концу реплики он уже был готов.
   - Один раз при старте попросить модель дать английские ключевые слова к каждому абзацу
     (пачками по 20–30), положить их в отдельный столбец FTS, кешировать вне репозитория по
     `index_sha256`. Задержки на вопрос не добавляет, но старт дольше и абзацы уходят в шлюз.

   Готово, когда на шести вопросах нужный абзац есть в выдаче минимум для пяти и первое
   предложение появляется не позже 2,5 с в медиане.

2. **Синонимы внутри языка.** Вопрос про интеграции не находится ни одним способом: в документах
   стоит «заглушки» и «отложено». Проверить, решает ли это вариант с ключевыми словами к абзацам
   из задачи 1; если нет — добавить в запрос ключевых слов просьбу давать слова, которыми это
   могло быть названо в рабочих документах.

3. **Повтор при зависании шлюза.** Если за 4 с не пришёл первый токен, отменить запрос и
   отправить его заново по новому соединению, один раз. Сейчас такой выброс стоит 14–20 с.

4. **Первое предложение на экран.** Сервер шлёт `say`, клиент в `ask()` только пишет его в
   журнал (`say_preview`). Показывать его как черновик и заменять текстом из `answer_core`.

5. **Ответы с цифрами.** Сейчас строка с цифрой ждёт конца ответа. Проверить вариант: показывать
   её сразу после строки `USE`, если все указанные там источники есть в выдаче.

6. **`docx` и `pdf`.** Индекс читает только `.md` и `.txt`; остальное теперь перечисляется в
   статусе. Решить: конвертировать при старте или не включать живой режим без подтверждения,
   пока список пропущенного не пуст.

## Чего замеры не показывают

- Живой звук из Meet и задержку распознавания конца реплики: мерился только путь подсказки.
- Другие модели шлюза: на бесплатном аккаунте из 65 доступны две, `gemma-4-31b` и
  `qwen3.5-4b-32k-fast`.
- Устойчивость цифр: один прогон.
- Интерфейс: `public/app.js` в этом PR не менялся и в браузере не запускался.
- Проверка шла на Windows: тест с симлинками там падает и на исходном коде, `node tests/ui.mjs`
  тоже.
